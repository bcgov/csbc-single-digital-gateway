PostgresCluster "{{ .Values.name }}" applied (Postgres {{ .Values.postgresVersion }},
{{ .Values.instances.replicas }} instance(s), pgBackRest repo1 on a {{ .Values.backups.storage.size }} PVC).

Requires the Crunchy Postgres Operator (PGO) already installed in the cluster/namespace.

Watch it come up:
  kubectl get postgrescluster {{ .Values.name }} -w
  kubectl get pods -l postgres-operator.crunchydata.com/cluster={{ .Values.name }}

Connection Secret (generated by the operator):
  {{ .Values.name }}-pguser-{{ .Values.database.user }}
  keys: uri, host, port, dbname, user, password, jdbc-uri
        {{- if .Values.pgbouncer.enabled }} (+ pgbouncer-host / pgbouncer-port / pgbouncer-uri){{- end }}

Wiring the apps (feature 75) — their env expects DATABASE_URL. The operator Secret uses the
key `uri` (a valid postgres:// URL), so map it per-key rather than via envFrom, e.g. add to the
app Deployment:

  env:
    - name: DATABASE_URL
      valueFrom:
        secretKeyRef:
          name: {{ .Values.name }}-pguser-{{ .Values.database.user }}
          key: uri{{ if .Values.pgbouncer.enabled }}   # or pgbouncer-uri to go through the pooler{{ end }}

(The app charts currently inject DATABASE_URL via envFrom an existingSecret with that exact key —
see the doc for the recommended `extraEnv` bridge.)
